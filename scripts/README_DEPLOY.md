# Инструкция для инженеров техподдержки: Развертывание агента NOC на кассах

Данное руководство предназначено для выездных инженеров и специалистов технической поддержки 1-й и 2-й линии. В нем описан процесс автоматической установки и подключения кассовых узлов 1С к центральному пульту мониторинга **NOC 1C Dashboard**.

---

## 1. Состав устанавливаемых компонентов

Пакетный скрипт `install.bat` выполняет полную автоматическую подготовку рабочего места кассира:
1. **Проверка прав администратора и блокировок**: предотвращает порчу базы 1С при активных сеансах кассиров.
2. **Обнаружение утилит удаленного доступа (AnyDesk / RuDesktop)**: динамически определяет идентификатор кассы без использования статических паролей в открытом виде.
3. **Безопасная конфигурация параметров подключения**: сохраняет URL сервера и токен авторизации в защищенное хранилище `%ProgramData%\1C-NOC` с ограничением прав (только Administrators и SYSTEM).
4. **Загрузка и внедрение расширения 1С (`_МониторСаппорта`, `support.cfe`)**: внедряет стелс-агент телеметрии через пакетный режим Конфигуратора без снятия конфигурации с замка.

---

## 2. Способы загрузки установщика на кассу

Установщик и актуальная сборка расширения доступны напрямую с центрального сервера NOC:

* **Пакетный установщик**: `http://<NOC_SERVER_IP>:3000/downloads/install.bat`
* **Файл расширения 1С**: `http://<NOC_SERVER_IP>:3000/downloads/support.cfe`
* **Манифест версий OTA**: `http://<NOC_SERVER_IP>:3000/downloads/version.json`

### Быстрая загрузка через PowerShell на кассе:
```powershell
Invoke-WebRequest -Uri "http://<NOC_SERVER_IP>:3000/downloads/install.bat" -OutFile "$env:TEMP\install.bat"
cd $env:TEMP
```

---

## 3. Инструкция по запуску

> ⚠️ **Важно**: Запуск скрипта **ОБЯЗАТЕЛЬНО** выполняется с повышенными привилегиями (**«Запуск от имени администратора»** / **Run as administrator**).

### Вариант А: Интерактивный режим (по умолчанию)
1. Нажмите правой кнопкой мыши по `install.bat` → выберите **«Запуск от имени администратора»**.
2. Введите путь к базе 1С (либо нажмите **Enter** для использования пути по умолчанию).
3. Введите адрес сервера NOC (например, `https://noc.company.local:3000`).
4. Введите токен авторизации кассы (`NOC_TOKEN`), выданный для торговой точки.
5. Дождитесь выполнения этапов установки и сообщения `[УСПЕХ]`.

### Вариант Б: Пакетный режим с передачей параметров командной строки
Формат вызова:
```cmd
install.bat "<ПутьКБазе>" "<NOC_SERVER_URL>" "<NOC_TOKEN>"
```

> ⚠️ **Предостережение**: Передача токена через аргумент командной строки может быть видна в диспетчере процессов операционной системы и журналах аудита. Для рабочих сред рекомендуется интерактивный ввод или предварительное создание защищенного `%ProgramData%\1C-NOC\config.json`.

Пример:
```cmd
install.bat "C:\1C_Bases\Shop42_POS1" "https://noc.company.local:3000" "your-device-token"
```

### Вариант В: Передача параметров через переменные среды
```cmd
set "NOC_SERVER_URL=https://noc.company.local:3000"
set "NOC_TOKEN=your-device-token"
install.bat "C:\1C_Bases\Retail"
```

## 4. Требования безопасности сетевого взаимодействия и ACL

1. **Обязательный HTTPS**:
   - Для удаленных серверов установщик требует протокол `https://` и валидные TLS-сертификаты. Использование ключа `-k` (отключение проверки сертификатов) запрещено.
   - Использование `http://` разрешено исключительно для локального стенда разработчика (`localhost` или `127.0.0.1`).
2. **Контроль целостности артефактов**:
   - Установщик проверяет код возврата загрузки, ненулевой размер и сигнатуру бинарного контейнера 1С (`FF FF FF 7F`).
   - *Необходимая схема защиты для production*: до перехода на изолированную службу внедряется верификация цифровой подписи манифеста OTA центральным корневым сертификатом NOC.
3. **Модель прав доступа (ACL) и контекст исполнения**:
   - В **файловой базе 1С** серверный BSL-код выполняется непосредственно в процессе `1cv8.exe` / `1cv8c.exe` под интерактивной учетной записью кассира (`Users`). Поэтому файлу `config.json` предоставляются права `Read` для локальных пользователей (`Users`), а полный доступ (`F`) зарезервирован за `Administrators` и `SYSTEM`.
   - В **клиент-серверном режиме** код исполняется под служебной учетной записью сервера 1С (например, `USR1CV8`).
   - ⚠️ **Архитектурный блокер**: До развертывания фоновой службы Windows (Фаза 4.2) полная изоляция секрета от процессов интерактивного пользователя кассы невозможна без нарушения работы расширения в файловой базе. Полная изоляция будет обеспечена переводом 1С на запись в локальный spool (Фаза 4.1), откуда служба Windows (Фаза 4.2) сама будет отправлять телеметрию. До проверки на реальном Windows-стенде статус Phase 4.0.1 подтвержден статическим анализом, но не физическим выполнением.

## 5. Порядок работы механизма Process Guard

Расширение 1С внедряется в монопольном режиме через ключ `/UpdateDBCfg`. 
- Если на кассе запущен клиент 1С (`1cv8.exe` или `1cv8c.exe`), скрипт выведет предупреждение:
  ```
  [ВНИМАНИЕ] Обнаружен запущенный процесс 1cv8.exe!
  Пожалуйста, закройте 1С на 30 секунд для безопасного внедрения расширения.
  ```
- Попросите кассира корректно выйти из 1С, нажмите любую клавишу, и скрипт продолжит установку автоматически.

## 6. Проверка успешности установки

После завершения скрипта выполните три быстрых шага верификации:

### Шаг 1. Проверка AnyDesk / RuDesktop
- Убедитесь, что установщик обнаружил AnyDesk или RuDesktop и вывел числовой ID кассы.
- Согласно политике безопасности NOC, статические сервисные пароли отключены во избежание компрометации доступа.
- Удаленное подключение выполняется по запросу кассира либо через централизованную корпоративную политику доступа.

### Шаг 2. Проверка расширения в 1С:Предприятие
1. Запустите 1С на кассе в режиме «1С:Предприятие» под учетной записью с правами администратора.
2. Перейдите: **Администрирование** → **Печатные формы, отчеты и обработки** → **Расширения** (или **Настройки** → **Расширения** в зависимости от типовой конфигурации).
3. Убедитесь, что в списке присутствует:
   - **Имя**: `_МониторСаппорта`
   - **Синоним**: `Монитор саппорта (NOC Telemetry)`
   - **Безопасный режим**: Отключен (флажок снят)
   - **Защита от опасных действий**: Отключена

### Шаг 3. Проверка на пульте NOC Dashboard
1. Откройте веб-интерфейс дашборда: `http://<NOC_SERVER_IP>:3000`.
2. Найдите кассу в списке соответствующего магазина.
3. В течение 5 секунд после входа кассира в 1С сработает стелс-старт телеметрии.
4. Статус кассы должен измениться на **«В сети / только что»** или **«N сек назад»**.
5. Проверьте актуальность метрик: статус кассовой смены, очередь неотправленных чеков ОФД и параметры системы.

## 7. Чек-лист устранения типовых неисправностей (Troubleshooting)

| Проблема | Причина | Способ решения |
|---|---|---|
| **`[ОШИБКА] Данный скрипт должен быть запущен с правами Администратора!`** | Запуск выполнен двойным кликом от непривилегированного пользователя Windows. | Запустите `cmd.exe` через «Запуск от имени администратора» и вызовите `install.bat`. |
| **`[ОШИБКА] Не указан путь к информационной базе 1С`** | Не введен путь при интерактивном запросе и не передан первый аргумент. | Укажите корректный каталог каталожной базы (например, `C:\1C_Bases\Retail`). |
| **`[ОШИБКА] Платформа 1С:Предприятие 8 не найдена`** | 1С установлена в нестандартный каталог или используется портативная версия. | Проверьте путь к платформе. При необходимости отредактируйте переменную `ONEC_EXE` в `install.bat` или создайте ярлык в `C:\Program Files\1cv8\common\1cestart.exe`. |
| **`[ОШИБКА] Не удалось скачать файл расширения support.cfe`** | Брандмауэр кассы или сетевой шлюз блокирует обращение к порту сервера NOC. | 1. Проверьте пинг: `ping <NOC_SERVER_IP>`.<br>2. Проверьте доступность порта: `curl -I https://<NOC_SERVER_IP>:3000/downloads/version.json`.<br>3. Разрешите входящий порт на сервере NOC. |
| **Ошибка Конфигуратора `Код возврата 1`** | База 1С заблокирована зависшим фоновым процессом или файлом `1Cv8.cfl` / `1Cv8.1CD`. | 1. Проверьте Диспетчер задач на наличие скрытых процессов `1cv8.exe`.<br>2. Проверьте лог установки в `%TEMP%\1c_extension_install.log`.<br>3. Убедитесь, что у текущего пользователя есть права записи в каталог базы. |
| **Касса не появляется на дашборде после запуска 1С** | Токен не сконфигурирован, в типовой конфигурации включен безопасный режим для расширения или заблокирован исходящий HTTP-трафик из 1С. | 1. Проверьте наличие `NOC_TOKEN` в `%ProgramData%\1C-NOC\config.json`.<br>2. В списке расширений 1С снимите галку «Безопасный режим».<br>3. Проверьте журнал регистрации 1С на наличие ошибок в процедуре `_МС_Сервер.ВыполнитьРегламентныйМониторинг()`. |
| **Удаленный доступ отображается как `NONE`** | Утилиты AnyDesk или RuDesktop не установлены на кассе либо запущены в портативном режиме без файла конфигурации в ProgramData. | Установите AnyDesk или RuDesktop в операционную систему. Расширение автоматически подхватит ID после запуска приложения. |

## 8. Дорожная карта разработки POS-агента (Roadmap Фаз 4.0 — 4.5)

| Фаза | Наименование | Статус | Содержание и зависимости |
| :--- | :--- | :--- | :--- |
| **Phase 4.0** | POS audit and architecture decisions | **Выполнено** | Аудит BSL, install.bat, рисков блокировок UI и паролей AnyDesk. Архитектурный план перехода на фоновую службу. |
| **Phase 4.0.1** | Installer security hardening: TLS, token handling, configuration and ACL | **Реализовано статически** | Удаление `curl -k`, обязательный HTTPS, защита токена, ACL с проверкой ошибок, фиксация блокера файловой базы, исправление BSL `ExpandEnvironmentStrings`. *Требует верификации на Windows.* |
| **Phase 4.1** | Lightweight 1C BSL extension / Zero-Freeze | **В очереди (Следующая задача)** | Удаление синхронных HTTP-вызовов и WMI/COM из потока 1С, атомарная запись в spool (`temp_<guid>.tmp` -> `<ts>_<guid>.json`). |
| **Phase 4.2** | Native Windows Service C++/Win32 and spool ingestion | **Заблокировано до Phase 4.1** | Служба C++/Win32 (`SERVICE_WIN32_OWN_PROCESS`), создание каталогов spool со строгими SECURITY_ATTRIBUTES, чтение spool через `ReadDirectoryChangesW`, изоляция в quarantine. |
| **Phase 4.3** | Bounded SQLite queue and asynchronous HTTP transport | **Запланировано** | Кольцевой буфер SQLite (лимит базы <= 10 МБ), асинхронный WinHTTP-клиент (TLS 1.2/1.3, gzip), сбор системных метрик Win32 API. |
| **Phase 4.4** | AnyDesk/RuDesktop ID discovery and configuration security | **Запланировано** | Безопасное чтение ID из конфигураций утилит в контексте SYSTEM, хранение секретов в защищенном реестре. |
| **Phase 4.5** | End-to-end testing, crash recovery, performance measurements and pilot rollout | **Запланировано** | Комплексное тестирование на реальных Windows POS, оффлайн 72ч (лимит 10 МБ), тесты Crash Recovery при обрыве питания, пилот. |
